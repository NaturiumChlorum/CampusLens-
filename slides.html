校园通知与任务管理

通知里的时间、地点和材料分散在长文本中，整理后还需要查询进度。

保留已有 HarmonyOS NEXT 界面、SQLite、任务管理、OCR 和系统日历，让自然语言直接连接已有业务。

原有规则识别仍独立保留，不能作为大模型 Tool Calling 的证明。

三个业务工具

模型可选工具实际执行
query_tasks读取 SQLite，按状态或时间查询
get_task_statistics从完整任务快照统计数量
create_task_draft生成待确认草稿，不直接写库

模型与应用的分工

  1. 模型接收自然语言与工具定义，返回工具名和参数。
  2. 应用检查白名单、参数和日期，执行真实业务。
  3. 应用回传带调用 ID 的实际结果，模型生成中文回复。
  4. 界面显示调用参数、执行结果和错误。
网关使用 DeepSeek Chat Completions 工具协议；不以关键词规则替代模型选择。

确认后才创建任务

草稿先保存在内存中。用户可以查看、修改或取消，只有确认页的保存操作能写入数据库。

日期严格校验，保存防止重复提交。模型工具中没有直接写库、删除任务或修改日历的入口。

未完成包含已过期；即将到期只按截止时间统计，活动时间不替代截止时间。

密钥留在服务端

模型 API Key 仅从服务端环境变量读取；原生应用只连接网关。

本机演示通过 hdc 端口映射连接回环地址。远程网关要求 HTTPS；对外监听要求访问凭据。

.env 与签名文件不进入 Git，HAP 不包含服务端环境文件。任务文本及工具结果会发送给模型，演示使用非敏感数据。
